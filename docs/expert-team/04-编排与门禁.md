## 1. 路由 Agent（仅分诊，不持 A）

- 路由 Agent **只分诊，不持 A**，按 RACI 派单到专家 Agent；
- 输入 →（识别事项类型）→（查 RACI：该事项 A/R/C/I）→（派单给对位的 R/C 专家 Agent）→（输出派单与待办，A 归人类首席）。

### 1.1 C 列唯一事实源（重要）

**C（咨询）名单以 `raci/RACI矩阵.csv` 的 C 列为准，本文件与 `agent-cards/00-路由Agent.md`、`.opencode/agents/router.md`
一律不再复制 C 名单。** 历史上三张表各抄一份，导致 19/20 行 C 与 RACI 不一致、6 行引入了 RACI 未授权的 C
（如支付域擅自加「合规」、缓存域擅自加「DevOps」）。现在改为引用，漂移在结构上不可能再发生。

- 本表只保留 **R（主派）与人类 A** 两列——领域到 Agent 是一一对应的，不存在歧义；
- 需要 C 时，router 取该事项在 RACI CSV 的 C 列；命中多条事项时取并集并遵守「C 咨询不超过 3 个」的上限，
  超出时按「风险等级优先 + 与 R 相关性」裁剪，并在派单日志备注写明裁剪原因；
- **加派例外（2026-09-26 真实派单实测发现）**：C 超出 CSV 时必须在结论中标注 `**加派·理由**`（不得静默扩大 C 集合），
  且**该条目的「需签批」必须为 Y**——原则偏离属人类裁定事项，Agent 不得自行吸收。

## 4. 事件驱动自动化（自主派单）

### 4.1 链路

```
本地 git 新提交 → autodispatch-watcher（增量取提交 + 单实例锁 + 注入隔离）
  → 创建 router 会话（agent=router）→ 按 路径路由规则.csv 强制加派专家
  → 专家出「结论块」→ router 写 派单日志.md + 待签批清单.md
  → 人类在 审批记录.md 签批 → approval-sync 生成 签批状态视图.md（积压/超期/孤儿）
  → dispatch-metrics 生成 度量看板.md（四态分布/采纳率/闭环时长）
```

### 4.2 脚本清单与语义（避免"未披露语义"）

| 脚本 | 作用 | 关键语义 |
| --- | --- | --- |
| `autodispatch-watcher.mjs` | 监听本地 git 新提交并派单 | **增量取提交**（`lastHead..HEAD`，无"最近 N 条"窗口盲区）；首次运行只建基线不派单；`--dry-run` 只报告不派单**且不写盘**；`--reset-baseline` 显式重建基线；状态损坏 → **fail-closed 退出**（绝不静默吞掉未评审提交）；单实例锁防并发重复派单；**传输层默认 `--transport=run`**（见下） |
| `approval-sync.mjs` | 签批闭环同步 | 纯机械同步，不做签批决定；`--strict` 卡「超期+孤儿签批」，`--require-closed` 才卡积压 |
| `dispatch-metrics.mjs` | 度量看板 | 只算可机械计算的 KPI；算不出的（误报率/漏审率/越权尝试）显式标注「需人工采集」，不假装有数 |
| `guard-audit.mjs` | 契约审计 | 写白名单精确性、专家只读、无明文密钥、单号三方一致、加固防回退 |
| `validate-expert-team.mjs` | 体系一致性 | 结构/引用/RACI 值/名册/门禁阈值/术语/自动化不变量，第 1~14 节 |
| `selftest.mjs` | 自动化自测 | watcher 纯函数与状态机不变量，CI 无模型可跑 |
| `ledger-doctor.mjs` | **派单后自检闭环** | 检测并自动修复台账结构问题（锚点错位/缺列/空行断表/重复单号/缺收尾竖线）；`--check` 供 CI，`--fix` 由 watcher 每次派单后自动调用 |

### 4.2.3 派单后自检闭环（router 无命令权，故自检下沉到代码）

router 的权限里没有命令执行权（`deny *` + 只放行 read/glob/grep/subagent），**它无法自己跑校验**。
而 2026-09-27 首次真实派单里，它手写台账同时犯了四类错，且**全部只静默丢数据、不报错**：

| 错误 | 静默后果 |
| --- | --- |
| 锚点插在表格中间 | 此后追加的所有行不被解析器读取 → 审计链无声断裂 |
| 数据行缺列（8≠9） | 该行被丢弃 |
| 数据行间混入空行 | 表被断成两段，解析器只读第一段 |
| 缺收尾竖线 / 单号重复 | 行损坏或统计翻倍 |

闭环做法（三层，缺一不可）：

1. **源头**：`router.md` 写入五戒（锚点在末尾 / 列数一致 / 无空行 / 收尾竖线 / 不重复）；
2. **运行时**：watcher 每次派单（含 mock）后立即 `ledger-doctor.mjs --fix`——可修的自动修（补列一律填「—」，**不臆造四态/需签批**），修不了的显式告警；
3. **CI**：`ledger-doctor.mjs --check` 作为第 ⑦ 步 + `validate` 第 15 节结构断言，红了不许合并。

> 修复逻辑本身是纯函数且要求**幂等**（对已规范的台账再跑一次无任何改动），`selftest` 第 14 组 20 条断言覆盖全部四类错误与幂等性。

### 4.2.1 派单传输层（1222 的关键修复）

派单**必须走 `opencode run`**（客户端内执行），不要用裸 `api post /api/session` + `/prompt`：

| 传输 | 命令 | 结论 |
| --- | --- | --- |
| `run`（默认，推荐） | `opencode run --agent router --title <t> --format json <prompt>`（cwd=仓库） | ✅ 额度归属正确，模型真实执行并产出结论 |
| `api`（兜底，不建议） | `api post /api/session` + `/prompt` | ❌ 免费额度下被判为「非 OpenCode 客户端」：**会话建成但 tokens=0、无任何结论**，且**不报错** |

- 一次真实派单会串多个专家子会话，**耗时可达 10~20 分钟**；`--dispatch-timeout` 默认 900s，常驻轮询靠 in-flight 互斥防叠加。
- watcher 会解析 `run` 的 JSONL 输出并判定 `结论产出=true/false`；若「有会话无结论」会在日志显式告警，
  台账不会出现新行——**判断派单是否真的生效，看台账而不是看 watcher 日志**。
- 通道异常时的处置：确认 provider 可用后 `--replay-last --once` 重放上一批。

### 4.2.2 通道健康与熔断（防「一次挂起毒化服务」）

真实事故（2026-09-26）：watcher 派单时未关闭子进程 stdin → CLI 阻塞在建会话之前 →
挂满超时 → **共享后台服务被楔死**，之后所有 `opencode run`（含最小提示词、含 `--standalone`）全部超时且**不能自愈**，必须人工重启桌面版。

三道防线（都已落代码 + 有 CI 断言）：

| 防线 | 机制 | 命令/参数 |
| --- | --- | --- |
| ① 不挂起 | 统一 `runCli()`：`spawn` + `stdin:['ignore',…]` + 显式 `stdin.end()` | — |
| ② 事前探活 | 派单前用最小提示词探活；**不通就不派单**（不推进 `lastHead`），记连续失败数 | `--health` 单独探活 |
| ③ 连续失败熔断 | 连续 3 次失败 → `open` 停止派单；熔断期间只做低成本探活，**连续 2 次探活通过**才自动恢复（防抖动） | `--reset-breaker` 人工复位 |

熔断状态机是纯函数（`breakerUpdate` / `breakerAllows`），`selftest` 第 12 组共 21 条断言在 CI 中无模型校验。

### 4.3 常驻与自启

| 场景 | 操作 |
| --- | --- |
| 临时常驻 | `node scripts\autodispatch-watcher.mjs --interval 120` |
| 安装开机自启 | `powershell -ExecutionPolicy Bypass -File scripts\install-autostart.ps1`（登录触发；崩溃 5 分钟后重试，最多 3 次；重复实例忽略） |
| 立即启动自启实例 | `Start-ScheduledTask -TaskName OpenCode-ExpertTeam-Autodispatch` |
| 卸载自启 | `powershell -ExecutionPolicy Bypass -File scripts\install-autostart.ps1 -Uninstall` |
| 查状态/日志 | `Get-ScheduledTask -TaskName OpenCode-ExpertTeam-Autodispatch`；日志 `logs\watcher.log` |

> 自启任务与手动实例共用**同一把单实例锁**：同时存在时后启动者会自行退出，不会重复派单。

### 4.4 运行手册（故障处置与回滚）

| 场景 | 处置 |
| --- | --- |
| 正常常驻 | `node scripts/autodispatch-watcher.mjs --interval 120`（Ctrl+C 优雅退出并释放锁） |
| **停常驻：三种方式别混用** | ① **交互式前台跑的**（自己敲的命令、能看到输出）→ `Ctrl+C`，走优雅退出、释放锁、写完状态；② **计划任务起的**（`Get-ScheduledTask` 显示 `Running`）→ 必须 `Stop-ScheduledTask` **再** `Stop-Process -Id <pid> -Force`，因为前者不杀子进程（见下方条目）；③ **两者都不确定** → 先查有没有残留进程（下方条目给了命令），有残留就按 ② 走。**在计划任务实例上按 Ctrl+C 无效**（没有前台控制台），而只做 ① 会留下持锁的孤儿进程 |
| 通道疑似不通 | `node scripts/autodispatch-watcher.mjs --health --once`；不通则查桌面版服务（必要时 `opencode service restart`） |
| 熔断中 | 看日志的 `⛔ 熔断中`；等通道自愈（连续 2 次探活通过自动恢复），或 `--reset-breaker --once` 人工复位 |
| 只想看会不会派单 | `--once --dry-run`（打印将派单条目 + 提示词预览） |
| 误派/重复派单 | 停 watcher → `--replay-last --once` 重放或人工在派单日志标注作废；状态里 `dispatches` 保留审计 |
| 状态文件损坏 | **不要删**。先备份，再用 `--state <新文件>` 另起状态；确认无未评审提交后才 `--reset-baseline` |
| 停计划任务后进程还在 | **实测 2026-09-27**：`Stop-ScheduledTask` 会把任务置回 `Ready`，但**不会杀掉它 spawn 出的 node 子进程**（子进程继续持有单实例锁）。必须再 `Stop-Process -Id <pid> -Force`。<br>**可复核步骤**：① `Start-ScheduledTask` → ② `Get-CimInstance Win32_Process -Filter "Name='node.exe'"` 记下 pid → ③ `Stop-ScheduledTask` → ④ `Get-ScheduledTask` 显示 `Ready` 但步骤②的 pid **仍在**、命令行含 `autodispatch-watcher.mjs --interval 120 --dispatch-timeout 3600` → ⑤ `Stop-Process -Id <pid> -Force` 后复查为空。<br>**证据**：`logs/watcher.log` 2026-09-27 02:29:20 常驻启动记录、02:30:10 随后的 `lock: 陈旧锁（pid=47400 已退出），本次接管`（证明进程确已退出后锁才被回收）；观察时刻 02:29:20→02:30:06 约 46 秒 |
| rebase/force-push 导致非线性 | 脚本会 fail-closed 并提示；人工确认后 `--reset-baseline` |
| 模型通道不可用（会话建了但无结论） | 属通道问题非脚本问题；派单日志无新增即为未留痕，通道恢复后 `--replay-last` |
| 签批积压/超期 | `node scripts/approval-sync.mjs` 看视图；`--strict` 作为 CI 卡口 |
| 门禁判定缺证据 | 结论降为「需人工」并写明缺哪项证据，不得以「已口头确认」替代 |
| **要看专家结论原文** | `node scripts/export-expert-conclusions.mjs`（**不要用消息 API**——它只返回 `{id,time,type,outcome}` 摘要，取不到原文）。`--main <sessionId>` 指定派单、`--out <路径>` 落盘、`--json` 出机读格式。退出码 2 = 有需人工判读的标记 |
| 专家结论缺块 | 按协议应标「数据缺失+已升级」并重派一次；`export-expert-conclusions.mjs` 会把「无结论块」显式标出 |
| 核验 dot 路径（`.github/`、`.gitignore`、`.opencode/`） | **禁用默认 glob**（`**` 不匹配前导点，实测 215 项里点路径 0 项）。用 `git ls-files <路径>` 或显式 `glob(".github/**/*")`。详见 `.opencode/agents/router.md`「核验纪律：点路径盲区」 |
| 怀疑提示注入被服从 | `export-expert-conclusions.mjs` 会标出越权表述与注入话术复述；**标记≠违规**（可能是在引述被拒绝的注入），须人工对照 `runbook/核对记录.md` 判读 |

> 边界重申：以上自动化**只做到「生成建议与待签批」为止**。签批、放行、发布永远由人类 A 完成。
> 同理，`export-expert-conclusions.mjs` **只摆证据不下结论**：它标出可疑措辞，但"是否被注入说服"由人判。
