# 04 · 多 Agent 编排与门禁

> 对应《体系文档》第 6 节。

## 1. 路由 Agent（仅分诊，不持 A）

- 路由 Agent **只分诊，不持 A**；
- 按 RACI 派单到专家 Agent；
- 输入 →（识别事项类型）→（查 RACI：该事项 A/R/C/I）→（派单给对位的 R/C 专家 Agent）→（输出派单与待办，A 归人类首席）。

**分诊决策表（示例）**

| 输入类型 | 主派 | 咨询（C） | 知会（I） |
| --- | --- | --- | --- |
| 新需求/需求变更 | 产品(01) | 架构/UI/QA/安全/合规 | 全员 |
| 需求排期冲突 | PMO(02) | 产品/各首席 | 治理委 |
| MR/diff 评审 | 对应域 Agent(09-12/04-08) | 架构/DBA/安全/QA | PMO |
| 测试放行请求 | 测试治理(14) | 架构/产品/安全/合规 | PMO |
| 发布计划 | DevOps(16) | 架构/各开发/DBA/安全/QA | 产品/PMO |
| 漏洞报告 | 安全(18) | 架构/DevOps/各开发/DBA | QA/PMO |
| 个保事件/PIA | 合规(19) | 安全/DBA/架构/产品/QA | 全员 |

> 对应 OpenCode 版本：`.opencode/agents/router.md`。

## 2. 七道强制门禁

**任一不过，不进下一阶段。**

| # | 门禁 | 关卡 | 判定主体（A） |
| --- | --- | --- | --- |
| 1 | 产品入场 | 合规/安全/数据分级前置评审 | 产品+合规 |
| 2 | 开发入场 | ADR / API契约 / SAST基础 / 个保影响标记 | 架构 |
| 3 | 测试门禁 | 功能逃逸率、自动化覆盖、合规用例（同意/注销/导出/保留） | QA治理 |
| 4 | 性能门禁 | 容量 / SLO / 压测 | QA性能 |
| 5 | 安全门禁 | SAST/DAST/SCA/密钥/IaC，**高危未修不发布** | 安全 |
| 6 | 合规门禁 | PIA、分类分级、用户权利流程、等保/密评待办 | 合规 |
| 7 | 发布门禁 | DevOps 错误预算、回滚预案、文档/ADR 归档 | DevOps |

## 3. 技术治理委员会（不增人）

- 组成：**架构 + 安全 + 合规 + DBA + QA治理 + DevOps**；
- 列席：产品 / PMO；
- 职责：**只仲裁跨域**（活动边界、路线争议、例外决策），**不替代各 A** 的日常责任。
