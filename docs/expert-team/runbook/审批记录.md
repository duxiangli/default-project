# 审批记录（人类首席签批台账）

> **本文件仅人类维护**：router 与专家 Agent 一律**不允许**写入本文件（权限见 `.opencode/agents/router.md`，校验脚本第 11 节强制检查）。
> **证据链**：`派单日志.md`（发生了什么）→ `待签批清单.md`（谁待批）→ 本文件（谁批了、批了什么、依据是什么）。

## 签批结论四态（与专家建议同构，但只有人类可落终态）

| 结论 | 含义 | 生效条件 |
| --- | --- | --- |
| 批准 | 事项按 R/C 建议方案执行 | 人类A签名 |
| 有条件批准 | 批准但带前置条件（如补齐某项门禁、限额度/限流量） | 人类A签名 + 条件清单 |
| 驳回 | 不执行，回退给 R 修订 | 人类A签名 + 理由 |
| 需人工 | 超出本岗权限/责任，升级至治理委员会或其他首席 | 人类A签名 + 升级对象 |

> 生产 / 个保 / 等保 / 安全高危的事项，按制度需会签/双签：主 A 必须签名，必要时并列会签人。

## 签批流（把「待签批清单」变成「已签批台账」）

1. 从 `docs/expert-team/runbook/待签批清单.md` 取一行（状态=待签批），或在 router 汇总中取待签批项；
2. 按「审批单模板」登记：核对专家建议四态、RACI、门禁状态、风险面与依据；
3. 给出**签批结论四态**之一，填写决策依据/条件；高危项按制度补会签/双签；
4. 回填 `待签批清单.md` 该行状态为「已签批·\<审批单号\>」（同一人工操作，避免口径漂移）；
5. 归档证据链接（派单日志行、专家建议、门禁记录）——本台账即审计证据。

## 约定

- 审批单号 `AP-YYYYMMDD-HHMM`，与派单号 `DSP-YYYYMMDD-HHMM` 一对一关联（router 预生成，人工可重编号）；
- 已签批记录不改写、不删除；同一事项再次变更须另起新审单；
- 跨域争议或超出给权：升级技术治理委员会，本台账留痕。
