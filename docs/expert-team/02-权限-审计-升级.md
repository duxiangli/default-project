# 02 · 权限、审计、升级

> 对应《体系文档》第 7 节。

## 1. 身份管理

| 项 | 要求 |
| --- | --- |
| 服务账号 | 每个 Agent **独立服务账号**，一人一票、一岗一账 |
| 凭证 | **短期凭证**（如 OIDC/STS 短时令牌），避免长期密钥 |
| 授权 | 按工具白名单授权；**默认只读，写操作单独授权** |

## 2. 风险分级

| 级别 | 示例 | 执行方式 |
| --- | --- | --- |
| 低 | 只读查询、指标汇总、文档生成 | **自动执行**，抽样审计 |
| 中 | 建 Jira、跑 SAST、出测试报告、改非生产配置 | **人工点批** 或限定范围后执行 |
| 高 | 生产发布、回滚、漏洞风险接受、PIA 通过、等保整改签批、敏感数据导出 | **人类 A 审批（可双签）**，禁止自动放行 |

> 生产 / 个保 / 等保 / 安全例外**不准自动**。建议高中风险启用双签（例如「域首席 + 合规/安全」组合）。

## 3. 全量留痕（审计库字段）

| 字段 | 说明 |
| --- | --- |
| 提示词版本 | 系统提示词哈希/版本号 |
| 输入摘要 | 工单号、输入来源、脱敏摘要 |
| 工具参数 | 每次工具调用的参数（脱敏后） |
| 输出 | Agent 结论文本 |
| 人工审批 | 审批人、动作、时间、依据 |
| 输出哈希 | 结论内容哈希，防篡改 |
| 工单号 | 关联 Jira/工单 |

- 个保 / 等保 / 安全事件按**适用保留期**留痕（个保法、等保 2.0、网安法要求）。
- 安全事件日志可用于追责与复盘。

## 4. 预算与熔断

- 按 **Agent / 工作流** 设 token 与调用次数上限；
- 超出预算：**异常自停**，触发告警并升级人工；
- 环比骤增（调用量/工具组合异常）视为越权尝试信号。

## 5. 升级路径

```
Agent → 人类首席 → 技术治理委员会 → CTO / 法务 / 安全官
```

- Agent 不自动跳过任何一级。
- **漏洞风险接受**例外链：DevSecOps → 安全架构 → 风险/合规 → CISO 类最终决策。

| 场景 | 升级对象 |
| --- | --- |
| 工具失败 / 数据缺失 | 对应人类首席 |
| 超权限 / 越权尝试 | 对应人类首席 + 安全 |
| 法律 / 个保 / 等保高风险 | 合规首席 + 法务 + 个保负责人 |
| 生产高风险 | 技术治理委员会 / CTO |
| 漏洞风险接受 | DevSecOps → 安全架构 → 风险/合规 → CISO |

## 6. 防提示注入

| 控制 | 做法 |
| --- | --- |
| 系统规则位置 | 系统提示词把治理规则放在**首尾**，中间为任务内容 |
| 输入隔离 | 用户/工单/diff 内容用 **XML/标记分隔**，视为不可信数据 |
| 输出脱敏 | 输出中 PII 自动脱敏，默认不下发原始身份信息 |
| 异常组合告警 | 异常的「工具组合 + 参数」调用组合自动告警，进入审计复核 |

> 各 Agent 的写权限、审计字段、升级对象再按 `agent-cards/` 岗位卡收窄。
