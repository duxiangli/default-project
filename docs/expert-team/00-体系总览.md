# 00 · 体系总览

> 本文档对应《20人资深专家＋专家Agent体系文档》第 1、2 节，是全体系的入口与总原则。目录结构与使用说明见仓库根目录 `README.md`。

## 1. 目的与范围

为 **Web/SaaS/移动端、涉个人信息、需安全/等保/合规评审** 的研发组织建立：

- **20 个不重复专家岗**，每岗一名 20 年+ 人类首席；
- 每岗配套一个**专家 Agent**，负责检索、起草、评审、催办、指标汇总；
- 跨域事项用 **RACI「一事一 A」**，Agent 不参与最终担责；
- 接 **Jira / GitLab / K8s / SAST / 个保台账 / 等保系统** 的可选工具集。

**适用平台**：内部自研 Agent 平台、Dify/Coze、LangGraph、AutoGen、GitLab Duo 类自定义 Agent 均可按本包改造。

## 2. 总原则

### 2.1 人类 A／Agent 执行

Agent 可作 **Executor / Responsible 草案**，但以下事项**必须人类首席签批**：

- 架构路线
- 安全漏洞接受
- 个保 PIA 结论
- 生产发布
- 人员绩效
- 合规放行

### 2.2 一事一 A

- 每个跨域活动**仅 1 个 Accountable**；
- **R** 可多人，**C** 事前咨询，**I** 事后知会；
- 共享 A 等于无 A。

### 2.3 最小权限

- Agent **默认只读**；
- 写工单 / 创分支 / 评论可限范围；
- **生产发布、删库、改权限、出个保结论一律人工审批**。

### 2.4 风险分级

| 级别 | 内容 | 执行方式 |
| --- | --- | --- |
| **低** | 只读查询、文档生成、指标汇总 | 可自动执行，抽样审计 |
| **中** | 建 Jira、跑 SAST、出测试报告、改非生产配置 | 人工审批，或限定范围后执行 |
| **高** | 生产发布、回滚、漏洞风险接受、PIA 通过、等保整改签批、敏感数据导出 | **只出建议，人类 A 审批** |

### 2.5 全量留痕

提示词版本、工具调用、依据、人工审批、输出哈希**入审计库**；个保/等保/安全事件可追溯。
