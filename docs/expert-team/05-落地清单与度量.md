# 05 · 落地清单与度量

> 对应《体系文档》第 8 节。

## 1. 落地清单

按顺序执行：

1. 按岗位卡（`agent-cards/01~20`）建 **20 个 Agent**，系统提示词统一套 `01-统一Agent骨架.md`；**先建立 20 位人类首席名册**（`roster/首席名册.csv`，单一事实源），改表后跑 `node scripts/sync-roster.mjs` + `node scripts/validate-expert-team.mjs`；
2. 接工具：**Jira / GitLab**（工单、diff、MR）、**K8s**（只读 + YAML 建议）、**SAST/DAST/SCA**、**个保台账**、**等保/密评系统**、**APM/DB监控**、**文档库**；
3. 把 `03-跨域RACI.md` / `raci/RACI矩阵.csv` **写进工单类型和发布检查单**；
4. 按岗位卡权限先 **只读试点**，再按岗位放开**中风险写操作**（人工点批）；
5. **每月**审：Agent 建议采纳率、误报、越权尝试、升级时长、门禁阻塞数。

## 2. 月度度量指标（KPI 口径建议）

| 指标 | 定义 | 目标方向 | 数据来源 |
| --- | --- | --- | --- |
| 建议采纳率 | 人类首席采纳的 Agent 结论 ÷ Agent 产出结论 | ≥ 80%（成熟后） | 审批记录/审计库 |
| 误报率 | 实际无需处置的报告 ÷ 总报告 | ≤ 15% | 各域报告闭环 |
| 越权尝试 | Agent 超出白名单工具/参数/权限的调用次数 | = 0 | 审计库/告警 |
| 升级时长 | Agent→人类首席的等待与响应时长（P50/P95） | 持续下降 | 工单时间戳 |
| 门禁阻塞数 | 7 道门禁中被挡下的事项数及根因分布 | 关注趋势 | 门禁记录 |
| 漏审率（抽检） | 抽样审计中被判「应拦未拦」的比例 | ≤ 2% | 抽样审计 |
| 可追溯率 | 结论可回溯到「提示词版本+工具调用+依据+审批」的比例 | 100% | 审计库完整性 |

## 3. 试点路线（建议 4~6 周）

| 阶段 | 内容 | 出口标准 |
| --- | --- | --- |
| W1 | 建 20 Agent + 骨架 + RACI 入工单 | 全员可调用、只读 |
| W2 | 接入 Jira/GitLab/SAST/个保台账 只读 | 取数可用 |
| W3 | 挑 5 个高价值岗（安全/合规/DevOps/QA/架构）试点评审 | 采纳率 ≥ 50% |
| W4 | 放开白名单中风险写操作（人工点批） | 越权尝试 = 0 |
| W5 | 7 道门禁 checklist 全量上线 | 门禁阻塞数可统计 |
| W6 | 治理委员会接管跨域仲裁 | 度量面板上线 |
