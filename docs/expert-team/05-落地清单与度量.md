# 05 · 落地清单与度量

> 对应《体系文档》第 8 节。**指标必须能被算出来**：本页把每个 KPI 标注为「脚本可算」或「需人工采集」，
> 脚本可算的由 `node scripts/dispatch-metrics.mjs` 生成（`runbook/度量看板.md`），需人工的不得假装有数。

## 1. 落地清单

按顺序执行：

1. 按岗位卡（`agent-cards/01~20`）建 **20 个 Agent**，系统提示词统一套 `01-统一Agent骨架.md` + 各卡「输出契约（结论块）」；
   **先建立 20 位人类首席名册**（`roster/首席名册.csv`，单一事实源），改表后跑 `node scripts/sync-roster.mjs` + `node scripts/validate-expert-team.mjs`；
2. 接工具：**Jira / GitLab**（工单、diff、MR）、**K8s**（只读 + YAML 建议）、**SAST/DAST/SCA**、**个保台账**、
   **等保/密评系统**、**APM/DB监控**、**文档库**；
3. 把 `03-跨域RACI.md` / `raci/RACI矩阵.csv` **写进工单类型和发布检查单**；把 `raci/门禁阈值.csv` 写进门禁 checklist；
4. 按岗位卡权限先 **只读试点**，再按岗位放开**中风险写操作**（人工点批）；
5. **每月**审：跑 `node scripts/dispatch-metrics.mjs`（自动指标）+ 人工采集项（见下表），复核 `guard-audit.mjs` 结论。

## 2. 月度度量指标（KPI 口径）

| 指标 | 定义（分子/分母） | 目标 | 数据来源 | 可算性 |
| --- | --- | --- | --- | --- |
| 建议采纳率 | 签批结论与专家建议四态**一致**的已闭环项 ÷ 四态可比较的已闭环项 | ≥ 80%（成熟后） | `审批记录.md` + `待签批清单.md` | **脚本可算**（`度量看板` 采纳率行） |
| 需签批率 | 需签批(Y)条目 ÷ 派单总数 | 监控趋势，无硬目标 | `派单日志.md` | **脚本可算** |
| 四态/严重度分布 | 各结论占比 + 不可解析数 | 不可解析率 → 0 | `派单日志.md` | **脚本可算** |
| 签批积压与账龄 | 未闭环数、最长/平均账龄、超期数（默认 >3 天） | 超期 = 0 | `待签批清单.md` | **脚本可算**（`签批状态视图.md`） |
| 签批闭环时长 | AP 入队时间 → 签批时间（精确到分），出 P50/P95 | 持续下降（需先有基线月） | `审批记录.md` 签批时间列 | **脚本可算** |
| 台账数据质量 | 单号可解析率、四态可解析率、需签批标记可解析率 | 均 = 100% | 三件套 | **脚本可算** |
| 门禁阻塞数 | 7 道门禁中被挡下事项数及根因分布 | 关注趋势 | 门禁判定（写在审批单证据列） | **半自动**：判定在审批单里，需人工归集根因 |
| 越权尝试 | Agent 超出白名单的调用次数 | = 0 | `guard-audit.mjs`（白名单精确性/只读/单号一致）+ OpenCode 服务侧工具调用审计 | **部分可算**：权限面可机械验证；被拒调用的**逐次计数仍缺数据源**，需 OpenCode 侧审计日志 |
| 误报率 | 实际无需处置的报告 ÷ 总报告 | ≤ 15% | 各域报告闭环 | **需人工**：三件套无「误报」字段，且「无需处置」是主观判断 |
| 漏审率（抽检） | 抽样中「应拦未拦」比例 | ≤ 2% | 抽样审计 | **需人工**：需先定抽样比例/样本量/抽样人/判定表 |
| 可追溯率 | 结论可回溯到「提示词版本+工具调用+输出哈希+门禁结论」的比例 | 100% | 审批单证据归档列 | **半自动**：模板已强制四项（`审批记录.md`），完整性可由 `guard-audit.mjs` 抽查 |

> 「成熟后」「持续下降」这类目标在**没有基线月数据前不可判定**；建议先跑满 1~2 个月形成基线，再定目标值。

## 3. 试点路线（4~6 周）

| 阶段 | 内容 | 出口标准（可判定） |
| --- | --- | --- |
| W1 | 建 20 Agent + 骨架 + 结论块契约 + RACI 入工单 | `validate-expert-team.mjs` 全绿；全员可调用、只读 |
| W2 | 接入 Jira/GitLab/SAST/个保台账 只读 | 取数可用；`guard-audit.mjs` 0 违规 |
| W3 | 挑 5 个高价值岗（安全/合规/DevOps/QA/架构）试点评审 | 采纳率 ≥ 50%（脚本可算，n≥20 条派单后才有意义） |
| W4 | 放开白名单中风险写操作（人工点批） | 越权尝试 = 0（以 `guard-audit.mjs` + OpenCode 侧审计为准） |
| W5 | 7 道门禁 checklist 全量上线（阈值取 `门禁阈值.csv`） | 门禁判定进入审批单证据列，阻塞数可归集 |
| W6 | 技术治理委员会（技术治理委员会）接管跨域仲裁 | 度量看板连续 2 个月产出且超期=0 |

## 4. 自动化例行（谁在什么时候跑什么）

| 时机 | 命令 | 作用 |
| --- | --- | --- |
| 改完岗位定义/名册/路由 | `node scripts/validate-expert-team.mjs` | 体系一致性 14 节校验 |
| 每次提交/派单后 | `node scripts/approval-sync.mjs` | 刷新签批状态视图（积压/超期/孤儿） |
| 每月复审 | `node scripts/dispatch-metrics.mjs` | 刷新度量看板 |
| 随时/发布前 | `node scripts/guard-audit.mjs --strict` | 治理契约审计（白名单/只读/密钥/单号一致/防回退） |
| CI（每次 push/PR） | 上述四项 + `node scripts/selftest.mjs` | 确定性检查全绿才允许合并 |
| 常驻 | `node scripts/autodispatch-watcher.mjs --interval 60` | 新提交自动派单（到"待签批"为止，签批仍由人做） |
